# Command boundary (R5E-210)

`accepted` means the kernel admitted a Command event. All seven operations are registered stubs; the result explicitly says `execution: not_implemented`. It does not mean a Task, Decision, session or push was executed. Canonical Command admissions reconstruct the semantic index on every start and lookup. Lifecycle result projection is a later integration.

A single local deployment uses one OS advisory lock in `/var/tmp/r5e-recurse-writer-<origin digest>/writer.lock`. The directory is derived from the canonical origin, never a caller-selected lock path. The helper holds `flock` until its owning runtime closes stdin or dies. A second process fails acquisition. The directory and lock must not be removed or replaced while any runtime exists. This is cooperative single-host ownership, not a distributed lease; deployments on different machines or isolated `/var/tmp` namespaces are unsupported. Local uncertainty markers are fsynced before submission and survive runtime restart; they never authorize work. No automatic stale-lock takeover exists.

The command digest covers operation, origin, target, expected predecessor and the canonical operation payload. Caller key comes from the verified signed request, not descriptive fields. The semantic index key is origin plus caller key plus command ID. Command specs retain the ID/digest, not private operational payload bytes. Callers must preserve the operation payload when they need it later.

Use command-ID lookup after a lost acknowledgement. An unresolved persisted marker keeps the result `outcome_unknown`; it never creates a new nonce or resubmits. An explicit protocol replay whose nonce already exists in canonical history is submitted to the kernel for its recorded denial; it is not interpreted as semantic deduplication. Ordinary same-ID retries with fresh protocol envelopes return the existing admission without execution.

The HTTP store uses digest-checked CAS history from the configured trusted kernel, not a claim of offline chain verification. Startup fails if history cannot be read or contains contradictory admitted command IDs. The future boot revocation gate must wrap this dispatcher before ordinary session mutation becomes available.

Denial reconstruction verifies the recorded `signed` envelope and binds its actor, origin, nonce, target and spec address. Authentication-stage denials never supply semantic Command identity: their transport body was not yet checked. Nonce claims are chain-wide, including wrong-origin denials, because the kernel claims the nonce before checking origin. The regression fixture in `test/fixtures/commands/authentication-denials.json` contains actual public records generated by `test/support/generate_command_denials.py` against a disposable isolated kernel.
