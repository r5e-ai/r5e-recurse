# Admission policy deployment

`R5eRecurse.Policy` is loaded in the deployment that hosts the kernel. Its upstream is fixed in code to `Recurse.Fold.Policy.Cedar`, whose upstream is `R5e.Policy.KernelCedar`. The standalone HTTP client application does not start a kernel or turn on this integration merely by being installed.

A deployment must load these modules and configure `config :r5e, policy: R5eRecurse.Policy` **before starting the kernel**. Keep the listener closed while the kernel replays and bootstrap runs. Then call `R5eRecurse.Policy.Boot.check!/0` before exposing the admission API. This hook raises if an active admitted Recurse PolicyBundle exists while the adapter or fixed upstream chain is absent, or if the descriptor for the deployed adapter has not been admitted. It raises when the required tracked-facts APIs are unavailable; an unavailable store is a startup failure, not evidence that no bundle exists. Do not put this hook in the HTTP client's application start: that can run before kernel replay and cannot establish the required chain fact.

Bootstrap admits the application Kind definitions, a node Endorsement over their explicit Kind paths, an operator Badge, the detached Cedar source and measured engine descriptor as CasObjects, and the operator's `recurse.r5e.io/v1alpha1/PolicyBundle/active`. `R5eRecurse.Policy.EngineBuild.measure/0` returns the descriptor bytes, address and CasObject spec. The descriptor measures the adapter and its presentation module as well as the kernel Cedar NIF and lockfile. Bootstrap must admit those exact bytes before opening the listener. Boot never silently replaces an operator's admitted bundle.

Operator signing stays outside runtime custody. R5E-210 supplies the bounded command helper and its `docs/operator-custody.md` contract: configured executable argv, pinned Ed25519 public key, exact DSSE PAE input, and local signature verification. The runtime key is never a fallback. Hardware compatibility requires evidence for the actual key and helper; a command interface alone does not establish it. Bootstrap accepts only the explicit driver selected by the deployment.

The bundle's `governs` list contains admitted application Kind paths and excludes PolicyBundle itself. The cited authority's narrowest links must cover that scope. Management admissions are checked for scope and Cedar syntax, then decided by upstream policy. The old Recurse bundle cannot veto its own replacement. These deployments are house instruments rooted in the operator's node authority; they do not establish independent governance or exclusive key custody.

Ordinary Recurse admissions require the active bundle and its available admitted source. The shipped `priv/policy/base.cedar` requires the three custody labels, nonempty resolved authority, and the SessionBinding key, Badge subject, delegation subject and AgentSession admission actor to agree. The binding must cite both credentials in its actual resolved authority, and name the current resource entry for the cited span admission. An agent binding needs provider and model. Node parents are walked through tracked resource reads; cycles, cross-graph parents and an overlong walk refuse admission.

Every Recurse path that reaches the adapter returns a Recurse policy block. Upstream refusals preserve their decision and evidence under `upstreamPolicy`, with `evaluated: false` and `reason: upstreamRefused` on the wrapper. Missing or malformed presentation is an error. Cedar evaluations cite the admitted bundle, source, measured engine and exact request/entity bytes through an EvaluationRecord. Generation conflicts fail closed without changing the nested Cedar result. The kernel independently captures every `Facts.fetch/1` resource generation and rechecks it at commit, including multi-hop reads and reads omitted by the adapter. Immutable event facts are required to be granted admissions before they establish identity.

A schema or authority refusal can happen before authorization and therefore has no Recurse evaluation. An admitted Recurse request that reached authorization but has no Recurse block is evidence that this adapter did not enforce it. Installing the client library alone is not an enforcement claim.

The deployment contract tests in `test/contract/policy_base_test.exs` need the kernel, fold, native Cedar engine and kernel test helpers loaded. They exercise the actual kernel HTTP router with signed requests, export verification under the house posture, and a fresh-chain bootstrap/rerun. The client-only test environment marks this suite skipped when the tracked-facts API is absent; a client-only green run is not enforcement evidence. Deployment CI must run the suite with those dependencies loaded and report zero skips.
