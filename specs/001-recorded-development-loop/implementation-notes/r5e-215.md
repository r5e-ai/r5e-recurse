# R5E-215 signing foundation

The signing service supports registered Prompt, LlmCall and ManagedRequest operations. T041/T042 remain incomplete: Review findings validation and the other required per-Kind paths are not implemented. Managed gateway routing, durable admission and recovery are separate integration work. Unsupported Kinds refuse; no fallback signer exists.

## Request and authority binding

`Signer.Request.prepare/2` accepts exactly `{kind, specBytes, authority}`, rejects duplicate JSON keys and caller-supplied request fields, and uses core canonical encoding. Closed shapes mirror the pinned gateway Prompt/LlmCall and local ManagedRequest Kinds. The runtime supplies the registered actor, role, span, body, model, upstream and exact authority refs. LlmCall resolves an admitted Prompt with the same span and exact body digest; it has no `requestBody` field. Optional provider, transport, requestPath and apiFormat must exactly match trusted `call_routing`, including absence. ManagedRequest must match the trusted expected spec and linked binding/LlmCall/body refs. Exact provider body bytes are never re-encoded.

`Signer.Authority.validate/2` rechecks complete snapshot hashes, payload digests, origin, credential signatures and projections, Badge countersignature, subject keys, exact session subject/role/Kind/task scope, and non-issuance. Core authority evaluation resolves parent terms, narrowing, succession and revocations. Both effective roots must match configured pins. Expiry is the earliest of five minutes and every cited-chain term end. Comparisons use core `Instant` on original strings, preserving accepted RFC3339 spellings and nanosecond precision. The current credential Kind patterns require uppercase T/Z; lowercase coverage exercises parser compatibility on synthetic histories, not current kernel credential acceptance. Actual admission coverage uses uppercase separators, -00:00 and nine fractional digits.

`Signer.Snapshot.read/3` reads complete canonical history and CAS payloads and verifies a second event read matches its head before recording observation time. The configured online kernel endpoint remains trusted for authenticity and current completeness; this is not an offline pinned-chain verifier. `record/3` checks signed admitted records and optional exact actor identity. Re-admissions resolve to an immutable event; cross-actor resource ambiguity refuses without an actor pin.

The reviewed enterprise policy-receipt branch also adds `gatewayContext` to LlmCall. This foundation mirrors the earlier pinned gateway schema and refuses that extra field. Gateway integration must explicitly bind the newer schema and context rather than strip policy inputs.

## Key custody and attempt lifecycle

`Signer.register/5` fixes an opaque slot to a trusted owner, generation, operation ID, Kind and request/authority contexts. Actor, role and authority must agree. Each generation/operation/Kind can register once; separate Prompt, LlmCall and ManagedRequest slots can share the HTTP operation ID. ManagedRequest's canonical operationId must equal that ID.

The first registration immutably binds the generation to the signer process in SessionKeys. Owner or signer death fences the generation synchronously, including before monitor delivery. Replacement signers cannot reuse that key with empty replay state. Bootstrap signing is an explicit pre-registration phase: raw SessionKeys.sign rejects a generation once its managed signer is bound, including a raw request dequeued after that transition.

A slot is consumed before validation, and request bodies/closures are released from retained slot state. Explicit key destruction notifies the signer to drop that generation's slots and operation tombstones, even if the owner stays alive. Owner death and custody-service death also remove retained state. Cleanup follows irreversible retirement; it cannot reopen a live operation ID. Failed attempts cannot re-sign. This in-memory fence does not establish the outcome of an earlier admission; the nonce journal and canonical reconciliation do that separately.

One monotonic attempt deadline starts before queueing or at Channel frame receipt (four seconds by default). Preflight and clock callbacks use a shared bounded worker helper. An unlinked watchdog monitors caller death, isolates asynchronous callback failures, and kills its worker on success, failure or deadline. Cancellable reply aliases and queued-result draining prevent late replies from crashing shared custody. This is callback lifetime management, not a guarantee over arbitrary trapping or unlinked descendants. Key custody checks the deadline, owner/signer binding, credential expiry and snapshot age when dequeued and again after signing. After verifying the cryptographic result, the signer requests a final serialized custody release decision. Custody evaluates the bounded clock, expiry and snapshot age, then checks the live owner/signer, exact public key and deadline. That successful check is the release authorization point; no later blocking callback precedes the returned envelope. Retirement after that point cannot retroactively retract an already authorized release. The envelope contains the exact eight-field canonical request and a fresh 16-byte nonce. Queued expired attempts never invoke crypto. If validity changes during crypto, the signature may have been computed but its result is suppressed; that is not a claim that no computation occurred. Outer calls allow five seconds. The Channel permits an eight-MiB encoded frame while the decoded spec remains capped at one MiB. Bridge death invalidates future route use and authentication; it does not cancel an already authenticated in-flight signing attempt. That attempt remains bounded by its original deadline and custody checks. A caller losing its reply must treat the operation as uncertain, never re-sign it through a replacement slot. Gateway integration must persist that uncertainty before enabling retries.

## Validation and remaining boundaries

Tests use actual Ed25519 signatures, parent credentials, Unix-socket authentication, replay and owner/key/signer death, reader failures, delayed monitor delivery, blocked callbacks, queued key operations, expired terms, snapshot aging, core timestamp variants and retained-state inspection. A disposable actual-kernel test bootstraps a scoped SessionBinding, signs Prompt → LlmCall → ManagedRequest through the real authenticated Channel, submits unchanged envelopes over HTTP, checks exact actors/authority/body references, and refuses a new operation after parent revocation. The fixed fold wrapper uses an explicitly admitted actor-scoped fixture workload policy and measured engine descriptor. ManagedRequest is manually constructed, gatewayContext is omitted, and no real provider forwarding or journal assembly is exercised; this is signing/admission integration, not the live gateway path.

The runtime must derive registration and verified record callbacks from admitted state. Preparing first-input equality, selecting semantic headers, resolving session binding/role, route ownership, process launch and dispatch are integration responsibilities. This foundation does not claim containment or that all development traffic is recorded. Review needs its actual Artifact/CAS findings path and T081 schema; no invented findings format is accepted.

Adversarial defects and their regressions are tracked in Recurse GitLab issue #6. This note describes the implementation boundary, not completion of R5E-215 or Phase 2.
