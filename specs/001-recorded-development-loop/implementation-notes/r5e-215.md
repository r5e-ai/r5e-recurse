# R5E-215 bounded request preparation

`Signer.Request.prepare/2` accepts only `{kind, specBytes, authority}` wire fields and returns the parsed candidate, original spec bytes, canonical spec bytes, computed address, registered target and registered authority order. It performs no cryptographic signing, admission, dispatch, generation/replay enforcement, or live authority evaluation. T041/T042 remain incomplete.

The trusted runtime context and verified-record callback contract are documented on the module. Only Prompt, LlmCall and ManagedRequest are supported; role allowlists further restrict them. Explicit closed shape checks mirror the current enterprise Prompt/LlmCall and local ManagedRequest Kinds. The pinned core verifier dependency provides canonical encoding but no reusable Schema validator. No production dependency on a sibling checkout is introduced.

LlmCall has no `requestBody` field: adding one is refused. Its Prompt reference resolves through the trusted callback to the exact admitted immutable Prompt, whose `contentRef` must identify the registered exact body bytes. Both records must use the registered span. LlmCall model and upstreamHost must match registration. Its optional provider, transport, requestPath and apiFormat fields must exactly match the registered `call_routing` map, including absence; callers cannot add values omitted by registration. Body bytes are digest checked without JSON decoding or re-encoding; provider bodies can contain numbers disallowed in canonical specs.

ManagedRequest must equal the trusted expected spec and independently match registered binding/LlmCall/body refs and body digest. Its linked LlmCall and Prompt are checked recursively. Preparing first-input equality, selecting non-secret semantic headers, and resolving the binding/role are responsibilities of trusted integration; this module does not establish them from untrusted assertions.

The callback must establish signature, origin, admitted outcome, ref identity and immutable resource version at a complete verified checkpoint. Neither a current resource projection nor an unchecked map is sufficient. This layer additionally checks returned ref, Kind, actor, closed spec shape and request binding. Callback failures return a bounded refusal without diagnostic payloads. Callback execution deadlines belong to the integrating signer process; this pure layer bounds spec input size, not callback duration.

Remaining R5E-215 work includes exact authority effectiveness/subjects/roots/terms/revocation checks, key and generation binding, nonce/expiry construction, operation replay fencing, DSSE creation, authenticated Channel integration, and other per-Kind validators. Review findings require their actual Artifact/CAS path and the T081 findings schema; there is no Review implementation or invented gateway field here.
