# R5E-217 bounded canonical harness provenance

`ManagedRequest.build/1` records `harnessInputs` in its canonical candidate and preserves the original inbound/outbound bytes. It parses duplicate-key-free JSON, resolves each RFC 6901 pointer to a decoded UTF-8 string, and hashes that string. No Unicode normalization or re-encoding of forwarded bytes occurs. Descriptors have exactly fieldPath, digest and provenance; digest is `sha256:` plus 64 lowercase hex digits. JSON-decoded pointer strings are unique, sorted by UTF-8 binary byte order, and cannot equal firstInput.fieldPath. Pointer tokens are never flattened: `/a~1b` and `/a/b` differ. Unsorted descriptors refuse; signed candidates are never rewritten.

The unreleased Kind makes harnessInputs optional structurally so earlier records remain readable. The current builder and signer require presence, including `[]`. Activation of the new admitted Recurse PolicyBundle source and measured adapter enables the admission rule for new submissions; there is no caller-selectable legacy mode. Historical absence means inventory not recorded, never an empty inventory. No old admission is rewritten or retroactively re-admitted.

Canonical policy uses immutable Facts.event grants to bind ManagedRequest actor, SessionBinding, exact Badge/delegation, task scope, admitted span, LlmCall and Prompt/body coordinates. Recorded resolvedRefs pin Prompt/span admission versions; mutable current projections do not replace historical identities. A resolved LlmCall is already recorded before this candidate can append; no speculative sequence or global history query is introduced.

Only two admitted provenance Kinds qualify: the exact bound ContextManifest with an inventoried harnessConfiguration digest; or a complete trace Artifact signed by the session, citing the same SessionBinding, whose content address equals bytes: plus the descriptor digest. The latter binds exact resulting text; Artifact.sources records claimed lineage, not causation. Direct ToolCall, Completion, LlmResponse and arbitrary events do not qualify.

Facts.event does not hydrate body bytes or prove inventory completeness. The trusted pinned adapter must identify the primary input consistently, classify supported added strings, compare its complete expected inventory before signing, and refuse unidentified additions or unsupported segmentation. The pure builder receives that inventory and cannot discover omitted provider-specific fields. First-request equality still requires trusted serialized first_request state and verified ContextManifest rendered bytes. Real harness isolation/configuration and omitted-input fixtures remain integration requirements.

No new Artifact signing surface is implemented. Transformed-text production remains blocked until authorized CAS capture and bounded session trace admission/recovery exist; canonical tests explicitly admit traces using test credentials. No managed gateway forwarding, authentication configuration, provider execution, or containment is claimed.
